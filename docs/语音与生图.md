# 云端语音与图片生成

在控制台的「TTS 语音」选择 Edge TTS、OpenAI 兼容云端语音或 MiniMax，在「AI 生图」配置图片模型。直接填写服务商提供的模型名，不需要将语音或生图模型加入聊天模型池。MiniMax 语音使用原生协议，其余云端服务使用 OpenAI 兼容协议。

## 语音

默认继续使用 Edge TTS，需要安装 `edge-tts`。切换到云端后，填写 API 地址、API Key、模型名和音色；不依赖 `edge-tts`。选择 OpenAI 兼容引擎时，地址填到 API 根路径，例如 `https://api.openai.com/v1`，服务会请求 `/audio/speech`。

Edge 的音色与语速、音量单独保留。云端音色支持自定义服务商的音色 ID，OpenAI 兼容引擎语速范围为 0.25–4 倍，MiniMax 为 0.5–2 倍。具体可用模型、音色和参数范围以服务商为准。试听先保存当前参数，再按保存后的引擎合成。

默认使用 `auto` 自动判断回复形式，无需逐次切换。系统结合当前消息与最终回复内容判断，开启上下文时还会参考最近最多 6 轮用户发言：短句陪伴、明确想听声音时倾向语音；不方便听、要求打字、代码、链接、列表、表格或超过最大字数时发送完整文字。最近明确的文字或语音意图优先于一般聊天倾向，当前表达可以覆盖此前意图。群聊还需要 @，且只在语音请求或语音输入时考虑语音。

自动判断使用本地规则，不额外调用模型；对含蓄、反讽等表达可能判断不准。仍可选择 `never / at_only / always` 保留固定策略；原有策略超过最大字数时会截断。语音总开关、账号开关、群组开关与引擎可用性继续生效，合成超时或失败时回复文字。QQ 语音发送失败时再补发一次文字，只有发送成功的内容才进入回复上下文。语音是 AI 合成声音。

这里的自动判断控制机器人的回复形式。QQ 纯语音消息尚未接入转写，当前不会自动理解录音内容；实时语音通话使用独立的 ASR 接入。

```yaml
tts:
  trigger: auto
  engine: openai
  base_url: https://api.openai.com/v1
  api_key: "${YUEXU_TTS_API_KEY:-}"
  model: "填写服务商的语音模型名"
  cloud_voice: alloy
  speed: 1.0
  timeout: 60
```

### MiniMax

选择「MiniMax 语音」，填写开放平台 API Key 后保存并试听。界面会填入默认地址、模型与音色；切换到另一云端引擎时需要重新填写密钥。支持直接填写 `speech-2.8-hd`、`speech-2.8-turbo`、`speech-2.6-hd`、`speech-2.6-turbo`、`speech-02-hd`、`speech-02-turbo` 等模型名，以及系统音色或已有的复刻音色 `voice_id`。

```yaml
tts:
  engine: minimax
  base_url: https://api.minimax.cn/v1
  api_key: "${YUEXU_TTS_API_KEY:-}"
  model: speech-2.8-hd
  cloud_voice: "Chinese (Mandarin)_Warm_Bestie"
  speed: 1.0
  timeout: 60
```

地址也可填 `https://api.minimax.cn` 或完整的 `https://api.minimax.cn/v1/t2a_v2`。服务使用 HTTP 同步合成，将返回的十六进制音频解码为 MP3，继续用于试听、缓存和机器人发送；服务报错、超时或音频无效时仍回退为文字。本次不包含音色复刻创建、WebSocket 流式合成或异步长文本任务。

接口及音色参考：[MiniMax HTTP 同步语音合成](https://platform.minimax.cn/docs/api-reference/speech-t2a-http)、[MiniMax 系统音色列表](https://platform.minimax.cn/docs/faq/system-voice-id)。

## 生图

在「AI 生图」填写地址、API Key、模型、尺寸并启用。地址同样填到 API 根路径，服务请求 `/images/generations`，每次生成一张。尺寸默认 `1024x1024`，需按模型支持的值填写。

保存后可在后台输入描述生成并预览，也可以向已接入的机器人发送：

```text
/image 一只坐在月光窗边的小猫，水彩风格
/draw 夜晚的森林与萤火虫
```

群聊仍需按账号设置 @ 机器人或使用唤醒词。指令经过现有限流、黑名单和屏蔽词检查后才会调用模型。

生图启用且配置可用时，QQ 个人账号（NapCat）的私聊支持 AI 自主配图：普通聊天或直接说“发张图片给我”，AI 会在同一轮聊天回复中结合话题决定是否生成一张图片，无需 `/image`，也不会每条都配图。QQ 语音通话中，图片发送到同一 QQ 私聊，回复文字继续通过通话播放。图片由 AI 生成，不冒充实拍；生图失败保留文字回复，自动配图可能产生服务商费用。

QQ 个人账号还支持主动消息自动配图：生图启用且配置可用时，「私聊惦记」和「活力 Agent」会在原有一轮聊天模型调用中，按话题与用户喜好决定是否生成一张风景、美食、小物等图片，无需 `/image`。普通文字可不配图，各自原有推送频次不变。图片由 AI 生成，不冒充实拍；生图失败回退文字且不重试，生成期间收到用户新消息或停推时取消发送。自动配图同样可能产生服务商费用；活力 Agent 的预览不调用生图。

```yaml
image_generation:
  enabled: true
  base_url: https://api.openai.com/v1
  api_key: "${YUEXU_IMAGE_API_KEY:-}"
  model: "填写服务商的生图模型名"
  size: 1024x1024
  timeout: 120
  cache_ttl_hours: 24
```

返回的 Base64 图片或公开图片 URL 会保存为本地图片，用于后台预览和通道发送。仅接收 PNG、JPEG、WebP；服务商返回 URL 时须可公开访问。图片缓存按保留时间随定时清理任务删除，长期需要的图片请自行保存。

## 通道与运行说明

- QQ 个人账号 / NapCat 使用媒体内容发送，支持后端与 NapCat 分处不同容器。
- Gewechat 沿用现有媒体发送接口，需协议服务能够读取媒体资源；独立部署时请核对协议服务的媒体地址要求。
- 当前 QQ 官方机器人和微信 ClawBot 适配器仅实现文字发送，因此保留文字回复，不调用无法发送的云端语音或生图服务；后台生成和预览仍可使用。
- 云端请求会产生服务商费用。前后台均不回显完整 API Key；更换 API 地址后需重新填写密钥。
- 缓存文件通过现有 `/static` 服务提供，持有文件 URL 的人可访问；不要把敏感内容用于公共部署的试听或生图。

接口格式参考官方文档：[语音合成](https://developers.openai.com/api/docs/guides/text-to-speech)、[图片生成](https://developers.openai.com/api/reference/resources/images/methods/generate)、[NapCat 媒体消息](https://napneko.github.io/onebot/segment)。

通话音频使用独立的通话入口：复用这里的 MiniMax 设置，通过 HTTP 流式合成 PCM，不经过 MP3 消息缓存。QQ 端仍需可用的通话媒体出口；本地 ASR 与通话桥的脚本说明见 [`deploy/voice_call/README.md`](../deploy/voice_call/README.md)。

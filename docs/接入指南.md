# 账号与机器人接入

更新：2026-10-23。控制台入口为「账号与机器人」。先配置可用模型，再添加连接并绑定人设。

| 通道 | 标识 | 登录与接收 | 本次能力 |
| --- | --- | --- | --- |
| 微信 ClawBot | `wechat_clawbot` | 微信扫码、必要时输入手机验证码；iLink 长轮询 | 私聊文本；收到语音转写时按文本处理 |
| QQ 官方机器人 | `qq_bot` | AppID / AppSecret；默认 WebSocket 长连接，也可 HTTPS 回调 | 单聊与群聊 @ 的文本收发 |
| QQ 个人账号 | `qq` | Windows 原生 / Linux Docker 自动准备后扫码；也可连接已有服务 | 个人账号功能；受管方式自动配置消息收发 |
| 微信个人账号 | `wechat` | 连接已有 Gewechat 服务扫码及事件桥接 | 历史兼容入口，上游已停止维护 |

机器人和个人账号共用人设、模型、上下文、记忆、日志与推送服务。新机器人通道暂不发送图片、表情或语音，界面禁用对应开关；ClawBot 不支持群聊。QQ 官方机器人不提供个人好友列表或普通 QQ 群列表。

## 微信 ClawBot

1. 在手机微信中启用 ClawBot，确认当前微信账号具备入口。
2. 点击「微信 ClawBot」→「开始扫码」，连接名称可留空。无需填写 Gewechat 地址或 Token。
3. 页面自动显示二维码，使用微信扫描，并在手机上确认。
4. 微信要求验证码时，将手机显示的验证码填入页面；二维码失效时点击「刷新二维码」。
5. 连接成功后，向 ClawBot 发送一条私聊消息。

登录凭据保存在本地账号数据库，接口响应不返回机器人 Token。服务重启后可按「自动连接」恢复；手动断开会停止接收并关闭自动连接，保存的凭据可用于再次点击「连接」。登录过期则需要重新扫码。

主动推送需要该用户先发消息，建立有效会话上下文。上下文只在当前连接进程中缓存，重启后需再次收到用户消息；失效时会给出错误并写入推送日志。不伪造会话 Token，也不承诺任意时间向任意微信用户推送。

实现依据：[腾讯 openclaw-weixin 官方项目](https://github.com/Tencent/openclaw-weixin)及其[协议说明](https://github.com/Tencent/openclaw-weixin/blob/main/docs/protocol.md)。

## QQ 官方机器人

1. 在 QQ 开放平台创建机器人，取得 AppID 与 AppSecret，并开通群聊、单聊事件权限。
2. 点击「QQ 官方机器人」，填写凭据，保留默认「长连接（本机可用）」并保存。
3. 点击「连接」。程序验证凭据并建立网关连接，成功收到 READY 才显示在线。
4. 从测试成员私聊机器人，或在已添加机器人的测试群中 @ 它。

默认只订阅 `GROUP_AND_C2C_EVENT (1 << 25)`。无需公网回调地址；网络中断会重试并尝试恢复网关会话。测试成员范围、IP 白名单、事件权限及消息发送限制按开放平台的实际配置执行。

如使用「HTTPS 事件回调」，保存后在设置里复制 `/api/bot/qq/{连接ID}`，用公网 HTTPS 域名替换本机地址，配置到开放平台并订阅消息事件。回调验证由程序签名响应，普通事件必须通过 Ed25519 验签；手动断开后不处理新的消息回调。避免同一机器人同时使用多个接收实例。

群与用户目标 ID 使用事件中的 OpenID，不能直接填写普通 QQ 号。被动回复携带原消息 ID，主动推送受平台权限与额度约束。

参考：[调用与鉴权](https://bot.q.qq.com/wiki/develop/api-v2/dev-prepare/interface-framework/api-use.html)、[事件与长连接](https://bot.q.qq.com/wiki/develop/api-v2/dev-prepare/interface-framework/event-emit.html)、[回调签名](https://bot.q.qq.com/wiki/develop/api-v2/dev-prepare/interface-framework/sign.html)。

## QQ 个人账号 / NapCat

### 自动配置，只需扫码

适用于 **Windows x64 电脑 / 服务器**，以及有本机 Docker Engine 的 **Linux x64 / arm64 服务器**。后端单进程启动，服务器无需图形界面；手机扫描浏览器中显示的二维码。

| 后端运行环境 | 自动准备方式 |
| --- | --- |
| Windows x64 Python | 原生 NapCat 完整包，无需预装 QQ 或 Docker |
| Linux x64 / arm64 Python | 通过本机 Docker socket 创建账号容器 |
| Linux 服务器 Docker | 使用[独立服务器 Compose](../deploy/docker/README.md#qq-自动扫码服务器方案)，后端与账号容器共享宿主机网络 |

运行方式默认 `adapters.napcat.runtime: auto`；管理员可明确指定 `native` 或 `docker`，当前分别支持 Windows x64 与 Linux。原 bridge Compose、macOS 及其它容器平台使用「连接已有 NapCat」。

1. 点击「QQ 个人账号」，保留「自动配置，只需扫码」，点击「开始扫码」。名称、人设和模型可暂不设置。
2. 页面依次显示检查环境、下载组件、自动配置和启动进度。Windows 首次下载约 124 MB 的 v4.18.41 Node 完整包并校验固定 SHA256；Linux 首次拉取固定版本与 digest 的官方多架构镜像。后续复用本机缓存。
3. 准备完成后自动显示二维码，使用手机 QQ 扫码并确认。程序自动配置本机 OneBot HTTP 发送和带独立 Token 的 HTTP 事件上报，不用手填端口、Token 或 WebSocket 地址。
4. 登录成功后开启自动连接。手动关闭自动连接后按设置执行；点击「断开连接」会停止该账号的运行环境。删除连接保留本地登录数据，不自动清除文件。

账号配置、随机凭据和实例归属保存在 `paths.data_dir/adapters/napcat/` 内，不改动已有 QQ / NapCat 安装。Windows 登录数据也保存在该目录；Linux 登录数据存入各账号独立的 Docker 命名数据卷。备份时同时保留数据库、该目录和对应数据卷，不要公开账号凭据。

下载失败可在弹窗点击「重新准备」，关闭弹窗只停止页面轮询，后台准备继续；再次扫码会接续查看准备状态。Windows 下载每个源最多尝试三次；来源支持强 ETag 与 Range 时中断后自动续传，否则安全重新下载。Docker 拉取同样有限重试并复用已缓存层。退出月叙会停止自身管理的进程或容器，保留登录数据；固定组件版本不会自动追新。

### 下载加速与离线包

Windows 可使用启动月叙进程的 `HTTPS_PROXY`，或由管理员在 `config.yaml` 为官方**同一完整包**配置 HTTPS 备用源：

```yaml
adapters:
  napcat:
    runtime: auto
    download_urls:
      - "${YUEXU_NAPCAT_DOWNLOAD_URL:-}"
      - https://downloads.example.com/NapCat.Shell.Windows.Node.zip
    offline_archive: ""
```

示例地址需替换为实际可用的可信源。`YUEXU_NAPCAT_DOWNLOAD_URL` 也可设置首选来源；失败后按配置顺序尝试，最后回退官方 GitHub 发布源。不同源仍校验同一 SHA256，不能换成其他版本或 Shell 精简包来绕过校验。

无法联网时，从 [v4.18.41 官方发布页](https://github.com/NapNeko/NapCatQQ/releases/tag/v4.18.41)取得 `NapCat.Shell.Windows.Node.zip`，不要解压。在 `adapters.napcat.offline_archive` 填写文件路径，例如 `D:/packages/NapCat.Shell.Windows.Node.zip`；相对路径按项目根目录解析。也可直接放到默认完整缓存位置 `data/adapters/napcat/runtime/v4.18.41.zip`。两种方式都会校验：

```text
SHA256: 51fbb10e7bcd56b0c2a6de86c37811e7518330e48a137ac689ab1e4d8627d3f0
```

下载中间文件是同目录的 `v4.18.41.part` 和 `v4.18.41.part.json`，需同时保留才能安全恢复；配置了自定义 `paths.data_dir` 时替换 `data`。校验失败的包不会执行，损坏断点会丢弃重下。

Linux 的镜像下载由 Docker daemon 完成，需要给 daemon 配置代理或镜像加速；仅设置月叙的 `HTTPS_PROXY` 不生效。支持 `YUEXU_NAPCAT_IMAGE` / `adapters.napcat.docker.image` 切换管理员维护的仓库，或使用 `docker save/load` 离线导入；完整命令和离线 tag 设置见[服务器部署](../deploy/docker/README.md#镜像下载慢或失败)。默认 socket 为 `/var/run/docker.sock`，可通过 `YUEXU_DOCKER_SOCKET` 调整。只让可信管理员管理该权限，不对公网开放 Docker API。

环境变量依赖配置中的 `${ENV:-默认值}` 占位符。若后台保存后 `config.yaml` 已写入具体值，请直接修改对应配置项或恢复占位符，重启后生效。

### 连接已有 NapCat

已有部署保持原设置；新建时选择「连接已有 NapCat」。NapCat 必须先在本机或可达主机上运行，以下两个服务的地址和 Token 各自独立：

| 配置 | 常见地址 | 用途 |
| --- | --- | --- |
| OneBot HTTP | `http://127.0.0.1:3000` | 登录资料、发送消息、群与好友列表 |
| NapCat WebUI | `http://127.0.0.1:6099` | WebUI 鉴权、获取及刷新 QQ 登录二维码 |

1. 添加「QQ 个人账号」，填写 OneBot HTTP 地址，以及 NapCat WebUI 地址和 **WebUI Token**。启用了 OneBot 鉴权时另填 OneBot Token。
2. 点击扫码登录。程序通过 `/api/auth/login` 获取 WebUI 临时凭据，再调用 `/api/QQLogin/GetQQLoginQrcode`。
3. WebUI 开启双重验证时，先在 NapCat WebUI 完成登录，再回到月叙点击「连接」。
4. 在 NapCat 网络配置中添加 WebSocket 客户端，连接到 `ws://127.0.0.1:8000/api/bot/onebot/ws/{连接ID}`。使用其他月叙端口时替换 `8000`；设置弹窗展示当前服务对应的地址。

OneBot HTTP 提供发送接口，接收消息还需要反向 WS。容器中的 `127.0.0.1` 指向容器自身，应改为可访问月叙的主机地址。

登录链接会在后端编码成 SVG 二维码，浏览器不再将登录链接直接当成图片加载。登录二维码不再写入公开静态目录。

参考：[NapCat QQLogin 路由源码](https://github.com/NapNeko/NapCatQQ/blob/main/packages/napcat-webui-backend/src/router/QQLogin.ts)。

## 微信个人账号 / Gewechat

此通道与 ClawBot 独立，只供**已有可运行服务**接入。[Gewechat 上游](https://github.com/Devo919/Gewechat)已停止维护，不再提供运行服务、Docker 镜像、部署方式和技术支持。月叙不提供自动安装，也不保证旧镜像仍可登录；保留此入口用于历史部署兼容。

1. 添加「微信个人账号」，API 地址通常为 `http://127.0.0.1:2531/v2/api`，按实际部署填写完整前缀。
2. Token、AppID 首次可留空。程序尝试获取 Token，扫码响应中的 AppID 会保存；请求使用 `X-GEWE-TOKEN`。
3. 点击扫码登录，确认后从 `loginInfo` 读取 wxid 与昵称。
4. 接收消息仍需部署侧事件桥接：现有 HTTP 入口 `/api/bot/onebot/{连接ID}` 需要后台 Bearer 鉴权，WS 入口使用相同连接 ID。Gewechat 原生回调不能直接当作无需鉴权的 HTTP 入口使用。

不同版本路径可通过 `adapter_config.endpoints` 调整。鉴权头、AppID 保存与登录状态解析已做兼容；由于上游 Gewechat 已停止维护，开源版未在真实服务上完成收发验证，因此不将其标为已联调完成。

## 常见失败

| 现象 | 检查 |
| --- | --- |
| 自动准备提示系统不支持 | 原生方式需 Windows x64；Linux x64 / arm64 需本机 Docker Engine 与服务器部署配置；其他平台连接已有 NapCat |
| 下载组件失败或校验不通过 | 保留下载断点，检查网络和空间后重新准备；可配置可信 HTTPS 备用源、启动进程代理或固定版本完整离线包 |
| 无法连接 Docker Engine | 检查 Docker 是否启动、后端是否有 socket 权限，以及容器是否挂载 socket；不要开放无鉴权 TCP API |
| 服务器镜像拉取失败 | 检查 Docker daemon 的代理 / 镜像加速，或预先导入同架构离线镜像并显式指定本地 tag |
| 自动启动失败 | 检查登录环境提示及受管目录内运行日志；不修改已有 QQ 安装 |
| QQ 提示缺少 WebUI Token | 填写管理面板 Token，不是 OneBot Token |
| 连接 6099 失败 | 启动 NapCat WebUI，确认地址、端口与容器网络 |
| `get_login_info` 返回 HTML / 404 | 当前地址不是 OneBot API，检查 NapCat 网络配置 |
| 微信个人账号返回 502 / 超时 | Gewechat 服务及完整 API 前缀是否可达 |
| ClawBot 已扫码仍未在线 | 手机确认、验证码、二维码有效期，以及是否已绑定其他实例 |
| QQ 官方机器人无法连接 | 开放平台权限、测试成员、IP 白名单与网络 |
| 在线但没有 AI 回复 | 模型是否连通、AI 开关、人设与群聊触发规则；查看消息和 AI 日志 |

默认按单进程运行。OneBot WS 仍沿用本机信任方式，没有独立 Token 校验；部署公网回调时仅开放需要的 QQ 官方机器人回调路径，不应将个人账号 WS 直接暴露到公网。

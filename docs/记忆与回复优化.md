# 记忆与回复优化记录

日期：2026-10-23。

本轮沿用现有记忆服务、关键词降级和上下文缓存，没有新增依赖或数据库字段。

| 环节 | 原问题 | 修改后的行为 |
| --- | --- | --- |
| 规则提取 | “我喜欢什么？”、假设和他人转述可能被截成用户事实 | 先判断源句，再从句首提取；保留真实自述、负面偏好和明确的“记住”请求 |
| 去重隔离 | 群聊事实可能阻止私聊保存相同事实 | 私聊、各群分别查重 |
| 召回降级 | 向量检索熔断后，具体问题直接返回空记忆 | 使用有超时限制的关键词兜底，继续应用账号、用户和群聊隔离 |
| 召回排序 | 先去重再排序可能留下较弱候选 | 先评分排序，再去掉相似内容 |
| 召回缓存 | 不同返回条数、近似字符预算、不同长问题可能复用结果 | 缓存区分实际条数、完整问题、作用域和精确预算，并保留有意义的标点 |
| 记忆提示 | 小预算被强制扩大，显式零预算被当成默认值 | 严格遵守传入预算，空间不足时不注入 |
| 多轮上下文 | 只限制单条长度，总历史可能远超预算 | 保留最近能容纳的完整轮次，维持时间顺序 |
| 回复组装 | 原始历史占满记忆空间，搜索参考未计入记忆预算 | 先计算搜索参考，为记忆预留空间，再按实际保留历史计算剩余预算 |
| 用户反馈 | 未注入提示词的记忆仍可能成为确认对象 | 只有注入了提示词的召回结果才进入本轮确认记录 |
| 索引重建 | 指定一个账号重建时也会清空共享向量集合 | 只重建指定账号，保留其他账号索引，并同步拒绝标记；全局重建保持原语义 |

自动测试使用内存 SQLite、关键词检索或可控的向量替身，不调用真实聊天模型或发送平台消息。测试覆盖记忆提取、私群隔离、熔断兜底、缓存、提示预算、回复分条和主动推送上下文兼容。

这些修改改善了记忆进入回复的依据和上下文完整性；实际措辞、事实理解和语义检索效果仍取决于配置的模型。复杂混合句的规则兜底采用保守策略，可能少记其中的真实陈述。

字符预算是长度估算，不是模型的 token 上限。系统人设、搜索参考和当前输入本身超过预算时保留原文，不再加入历史；如需严格限制模型窗口，应继续增加按模型计算 token 的校验。

已有历史记忆保留，不自动清洗或删除。本轮没有做真实模型回复质量的 A/B 对比。

## 2026-10-24 聊天语气与主动接话

在 `CharacterService` 组装提示词时统一补充聊天节奏要求，已有自定义模板也能生效，不改写保存的人设档案。后台风格、表情和长度参数继续覆盖默认倾向。

- 日常回复先接本轮具体的话和情绪，普通接话一两句即可，认真提问仍答完整；减少客服开场、复述和每轮问句收尾。
- 保留角色的态度和边界，亲近程度跟随已有对话。对方累、忙或不想聊时自然收尾，不用委屈或吃醋索取关注，不编造现实活动。
- 主动消息优先接最近聊到的小细节；后续接话补充或收尾，避免重新开场和重复盘问。与上条文字相同、仅标点空白表情不同的接话会拒发并留痕，不再重试。

语感示例只作参考，不作为固定话术：“今天好累，不太想说话”可以接“那先歇会儿，想说的时候再聊”；之前聊过猫团子，可以从“忽然想到团子了，有没有新照片”切入，不能凭空补出猫的近况。

没有新增依赖、数据库字段或发送频次。回归使用内存数据库、假模型和假适配器，不发送真实消息；实际语气仍需结合所配置模型观察。

## 2026-10-25 摘要细节与记忆管理

记忆通过两个时机写入：对话过程中提取独立事实；对话静默后，后台将尚未记录的内容按事件整理为历史笔记。示例配置静默时间为 600 秒、检查间隔为 300 秒，因此通常在最后一次对话后约 10–15 分钟记笔记，并不依赖“再见”等结束语。上下文超过模型预算或配置轮数时才滚动压缩，原始对话继续归档。

- 单个约 2000 字段落最多提取 8 条事实，替代原来的 3 条上限；模型提取输出预算同步增加。
- 分段笔记最多 1200 字（包含日期、用户归属），保留事件细节、约定、未完成计划及更正；工作摘要按上下文预算取四分之一，最多 1200 字。
- 超长单条及超长问答分段处理；合并笔记时逐段调用，避免再次把整段历史塞进一个请求。生成或合并失败时保留原文，重试复用已入库的分段笔记。
- 召回仍遵守每条 160 字和总提示预算，但长笔记优先选择与当前问题相关的片段，同时保留日期、用户归属。
- 管理页将记忆库选择放在概况区，常用搜索前置，高级筛选折叠并显示启用数量；对话摘要有独立标识和全文详情，手机使用紧凑统计及卡片列表。

旧摘要不会自动补全；已被截断的内容需要从仍保留的原始历史重新提取。更充分的提取和摘要可能增加模型用量；极小模型窗口仍可能拒绝摘要请求，此时原文会保留。

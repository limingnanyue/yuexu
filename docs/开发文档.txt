## 1\. 项目概述

### 1\.1 项目名称

**月叙**

寓意：月下叙话，侧重于陪伴式对话、记忆留存、拟人交流，贴合机器人聊天记忆的核心定位。如需更换名称，全文全局替换「月叙 / yuexu」即可。

### 1\.2 项目定位

跨QQ、微信双平台拟人AI聊天机器人，支持多账号同时扫码挂机，可自动响应私聊、群@、关键词触发对话；自带全套群管理能力；搭载**独立上下文会话管理 \+ 短期滑动窗口记忆 \+ 向量长期记忆**，分层实现拟人记忆；支持发送文字、表情包、语音；原生集成DeepSeek联网搜索能力，可实时检索时效性信息；支持后台配置自动发消息任务；配套独立Web控制面板，所有参数可视化配置。

代码采用严格分层模块化设计，职责隔离，每个业务独立为Service，数据访问独立Repository，协议适配单独封装，避免单个文件代码臃肿，便于迭代、调试、新增功能；配套Git提交规范，避免测试文件、敏感配置提交到仓库。

### 1\.3 功能清单汇总

- ✅ QQ、微信独立扫码登录，多账号同时在线

- ✅ 私聊、群聊自动应答，@触发、关键词触发、正则触发

- ✅ 群组管理：入群欢迎、退群记录、黑名单、关键词拦截、防刷屏、禁言

- ✅ **自动消息推送：定时自动发消息、周期推送、单次延时推送，支持群/私聊推送文字、表情、语音**【新增】

- ✅ 拟人设定：角色卡片、性格、语气、禁忌、自定义System Prompt，支持全局/单账号/单群独立人设

- ✅ **上下文会话管理：会话隔离、会话冻结/解冻、手动清空上下文、会话过期自动回收、独立会话TTL配置**【新增】

- ✅ 双层记忆：Redis短期滑动窗口记忆 \+ Chroma向量长期记忆，私聊/群记忆隔离

- ✅ LLM多模型配置，兼容OpenAI格式接口（DeepSeek、Ollama、豆包、通义千问等）

- ✅ DeepSeek Search API联网搜索，独立开关、自动识别时效问题触发搜索

- ✅ TTS语音生成与发送，支持多音色、语速调节、缓存自动清理

- ✅ 表情包库管理、关键词绑定表情、LLM标签解析自动发送表情

- ✅ 完整日志：消息日志、AI请求日志、搜索日志、推送任务日志、操作报错日志，支持检索导出

- ✅ 状态面板、数据统计、数据备份、服务启停管理

- ✅ Windows本地、Linux服务器双部署方案

- ✅ Git提交规范，禁止提交测试文件、本地缓存、敏感密钥配置【新增】

## 2\. 整体技术栈

### 2\.1 协议适配层

- QQ：NapCatQQ，输出 OneBot11 WS 协议

- 微信：Gewechat，HTTP/WS接口，适配OneBot11消息归一化

- 统一消息标准：OneBot11

### 2\.2 后端核心（FastAPI）

- Web框架：FastAPI

- ORM：SQLAlchemy

- 定时任务：APScheduler（同时承载定时推送、定时清理、定时备份）

- 缓存：Redis（**上下文会话存储、短期会话、限流缓存、会话TTL管理**）

- 向量库：Chroma（本地部署）；服务器高并发可替换为Qdrant

- 数据库：SQLite（Windows本地） / PostgreSQL（Linux服务端）

- TTS：Edge\-TTS（默认免费），预留火山TTS、阿里TTS接入

- 联网搜索：DeepSeek Search API

- 日志：Python logging，结构化日志入库

### 2\.3 前端面板

- Vue3 \+ Vite \+ Element Plus

- 状态管理：Pinia

- 网络请求：Axios

### 2\.4 部署 \& 版本管理

- Windows：绿色一键启动包，内置依赖、静态资源

- Linux：Docker \+ Docker Compose，容器编排

- 版本管理：Git \+ \.gitignore 管控，隔离开发测试文件

## 3\. 模块化架构与目录规范

> 架构原则：路由层（仅参数校验、转发）→ Service业务层（核心逻辑）→ Repository数据层（仅读写）→ Adapter适配层（平台差异隔离）→ Common公共工具
> 
> 禁止在路由层写业务；禁止Service直接操作数据库；适配器只做协议转换，不参与AI、记忆逻辑；模块之间依赖通过接口调用，禁止跨模块直接导入内部函数。
> 
>

## 4\. 核心模块详细设计

### 4\.1 账号与登录模块 `account_service`

1. 功能

    - 后台生成登录二维码，轮询查询扫码状态

    - 支持多QQ、多微信账号绑定，账号相互独立

    - 账号状态：未登录 / 登录中 / 在线 / 离线 / 风控异常 / 连接失败

    - 支持手动下线、重连、查看登录日志

    - 每个账号独立绑定：人设、模型、群规则、搜索开关、语音表情开关、推送权限

2. 数据存储：账号表保存平台类型、适配器地址、配置绑定关系、最后在线时间

### 4\.2 消息分发调度模块 `bot_dispatch_service`（核心总入口）

所有OneBot上报消息统一进入分发中心，串行执行如下流程：

1. 消息入队，限流风控校验（rate\_limit\_service）

2. 黑白名单、屏蔽词过滤

3. 判断是否命中固定关键词回复；命中直接返回固定消息，跳过AI

4. 读取会话上下文（context\_service），校验会话是否冻结、是否过期

5. 判断是否开启联网搜索：自动识别时效类问题 / 用户手动`/search`指令触发 → 调用`search_service`获取摘要

6. 读取当前会话对应的人设（全局→账号→群/私聊，就近覆盖）

7. 检索Chroma长期向量记忆，拼接进prompt

8. 调用`llm_service`请求大模型

9. 解析LLM返回内容，识别表情标签、语音标记

10. 组装统一分段消息结构（text / emoji / voice）

11. 交给对应adapter，翻译成QQ/微信原生消息发送

12. **更新上下文会话记录（context\_service）**

13. 记录消息日志、AI调用日志

> 设计优势：新增功能只需要在分发链路增加钩子，不需要大面积修改多处代码。
> 
> 

### 4\.3 群组管理模块 `group_admin_service`

- 入群欢迎、退群记录、新人提示

- 防刷屏：频率检测，短时间高频消息自动拦截、临时禁言

- 黑名单、违规关键词库，命中自动拦截、踢人、禁言

- 权限校验：区分主人、群管理员、普通成员，限制指令使用权限

- 单群独立开关：可单独关闭AI、关闭表情、关闭语音、关闭自动推送

### 4\.4 拟人角色人设模块 `character_service`

1. 后台可视化编辑人设卡片：角色名称、性格、说话风格、背景设定、禁止话题、回复底线

2. 三级覆盖策略：全局默认人设 \< 账号绑定人设 \< 单群专属人设

3. 自动组装System Prompt，支持预览Prompt、模板导出备份

4. 人设生效范围可配置：仅私聊 / 仅群聊 / 全部场景

### 4\.5 双层智能记忆库模块 `memory_service`

> 记忆和上下文做解耦：上下文=本次对话历史窗口（短期会话链路）；向量记忆=跨会话长期事实存储
> 
> 

- **短期记忆（Redis滑动窗口）**

保存当前对话N轮上下文，维持对话连贯性；窗口长度后台可配置；区分独立会话（私聊按用户ID，群聊按群\+用户ID）。

- **长期向量记忆（Chroma）**

自动提取对话内关键事实、用户偏好、个人信息，向量化存入向量库；用户新消息到来时，检索相关性高的历史记忆，注入prompt；**表情标记、语音标记不会写入向量库，防止记忆污染**。

- 记忆运维：后台可按用户/群检索记忆、单条删除、批量重置、导出记忆；支持记忆功能全局/单账号/单群关闭。

### 4\.6 上下文会话管理模块 `context_service`【新增】

上下文与会话ID强绑定，和向量记忆分离，专门管控单次对话会话生命周期：

1. 会话隔离规则

    - 私聊会话key：`ctx:private:{bot_id}:{user_id}`

    - 群聊会话key：`ctx:group:{bot_id}:{group_id}:{user_id}`

2. 核心能力

    - 会话TTL过期自动回收：后台可配置超时时间（例如10分钟无消息自动清空上下文）

    - 手动管理：后台/指令支持**清空指定会话上下文、冻结会话、解冻会话**；冻结状态下不再追加对话轮次

    - 窗口长度限制：独立配置单会话最大轮数，超过后自动淘汰最早一轮（滑动窗口）

    - 会话快照：支持查看当前会话全部历史上下文

    - 开关：全局/账号/单群可关闭上下文连续对话（一问一答模式，不保留历史）

3. 存储：全部存Redis，持久化开关可选；会话过期自动清理，不占用资源

4. 指令示例：`/clearctx` 清空当前会话上下文；后台面板批量清理过期会话

### 4\.7 LLM模型对接模块 `llm_service`

- 兼容所有OpenAI格式API，DeepSeek、Ollama、豆包等直接接入

- 模型参数可配置：api地址、key、model名称、temperature、top\_p、最大输出、超时

- 三级覆盖：全局默认模型 \< 账号模型 \< 单群模型

- 自动拼接：人设prompt \+ 检索到的长期记忆 \+ 当前上下文 \+ 搜索结果摘要

- 失败降级：接口超时、报错时返回兜底话术，写入错误日志

### 4\.8 DeepSeek联网搜索模块 `search_service`（独立解耦）

> 独立服务，和LLM解耦，搜索服务异常不会导致基础对话崩溃
> 
> 

1. 后台配置项：DeepSeek Search API Key、单次返回摘要条数、摘要最大长度、搜索超时

2. 三级开关：全局总开关、账号开关、单群开关

3. 两种触发模式

    - 自动触发：LLM前置判断问题是否需要时效性信息，自动调用搜索

    - 指令触发：`/search 问题`强制检索

4. 流程：调用DeepSeek Search API → 清洗、压缩网页摘要 → 作为参考资料追加到LLM上下文

5. 日志独立记录搜索query、返回摘要、耗时；后台搜索日志页面查看

6. 预留抽象层，后续可替换其他搜索源，无需改动上层分发逻辑

### 4\.9 TTS语音模块 `tts_service`

- 默认引擎Edge\-TTS（免费离线），预留火山TTS、阿里TTS切换

- 后台配置：音色、语速、音量、触发规则（仅@才语音 / 私聊自动语音）

- 流程：文本 → TTS生成mp3 → 写入voice\_cache → adapter发送语音消息

- 定时任务自动清理过期语音缓存，避免磁盘占用

- 长文本自动截断拆分；多媒体消息单独限流，风控优先级更高

- 开关控制：全局、账号、单群是否开启语音输出

### 4\.10 表情包管理模块 `emoji_service`

1. 后台表情库：上传图片表情、设置别名、分类、随机权重

2. 三种触发方式

    - LLM输出标签解析，例如`[开心]`自动替换表情

    - 关键词绑定，命中关键词自动追加表情

    - 人设配置固定附带表情

3. 适配封装：上层统一emoji消息段，NapCat、Gewechat各自适配平台表情接口

4. 开关：可全局/单账号/单群关闭表情发送

### 4\.11 自动消息推送模块 `auto_push_service`【新增】

依托APScheduler定时调度，独立任务管理，和AI对话链路解耦，支持主动发消息，不依赖用户触发：

1. 任务类型

    - 一次性延时推送：创建后延迟N分钟发送一次

    - 定时定点推送：cron表达式（每天8点、每周一）

    - 循环周期推送：间隔N分钟/小时循环推送

2. 推送目标：指定群聊、指定私聊好友，绑定到指定机器人账号

3. 推送内容段：支持text、emoji、voice组合消息段，和AI回复消息结构统一

4. 任务管理：后台新增、编辑、启停、删除推送任务；支持临时暂停任务

5. 风控：推送单独限流、随机发送间隔、单日推送次数上限，防止批量推送封号

6. 日志：独立推送日志，记录是否发送成功、失败原因

7. 权限：仅主人/管理员可创建自动推送任务，普通用户无权新建推送

### 4\.12 限流风控模块 `rate_limit_service`

- 消息频率限制、单账号单位时间消息上限

- 文字、表情、语音、自动推送消息分开限流，自动推送限流标准更严格

- 消息发送增加随机延时，规避平台风控

- 超限直接拦截，记录告警日志，不继续走AI链路

## 8\. 部署方案

### 8\.1 Windows本地部署

- 数据库：SQLite，向量库Chroma本地持久化

- Redis可以使用嵌入式Redis或独立简易版

- 打包为绿色启动包，一键运行，自动拉起后端\+前端静态资源

- 适合个人自用、调试测试

### 8\.2 Linux服务器Docker Compose部署

- PostgreSQL \+ Redis \+ Qdrant（可选） \+ 后端服务 \+ Nginx托管前端

- 编排文件一键启动，支持7×24小时挂机

- 适合长期在线、多账号场景

## 10\. 异常、风控与容错机制

1. 适配器断开：state\_manager检测连接状态，自动尝试重连，后台标记异常

2. LLM接口超时、报错：降级返回兜底话术，记录错误日志，不阻断机器人整体运行

3. 搜索API失败：自动跳过搜索，直接使用基础LLM对话

4. TTS生成失败：静默丢弃语音，只发送文字

5. 表情资源丢失：跳过表情，不打断回复

6. 消息超限限流：直接拦截，日志告警

7. 自动推送任务发送失败：自动重试（有限次数），失败写入推送日志，不阻塞其他任务

8. 会话上下文Redis异常：降级为无上下文一问一答模式，不崩溃

9. 数据定时备份，支持手动备份、一键恢复

## 12\. 开发规范约束（强制）

1. 禁止业务代码写在路由文件main\.py、router下

2. 所有数据库读写必须经过repository层

3. 所有平台消息发送，必须走adapter抽象接口，禁止直接硬编码平台协议

4. 每个service、repository、adapter独立单文件，文件行数建议控制在800行以内

5. 所有配置项从config\_loader读取，禁止硬编码密钥、地址

6. 所有外部API调用（LLM、搜索、TTS）增加超时捕获、异常日志

7. 所有用户输入做清洗过滤，防止prompt注入

8. Git提交严格遵循忽略清单，严禁密钥、测试缓存、本地数据库入仓库
